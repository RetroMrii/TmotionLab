# TmotionLab Reading Studio & Research Edition

React + TypeScript + Vite + React Router, with self-hosted Geist. One active
stylesheet (`src/index.css`) defines both themes. CSS, WAAPI and a lightweight SVG path loop implement motion;
no animation or chart library is required.

## Run locally

From the repository root:

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev -- --host 127.0.0.1
```

Start the API separately:

```powershell
.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

The API defaults to `http://127.0.0.1:8000`. Set `VITE_API_BASE_URL` at dev/build
startup to override it. The API must allow the frontend origin through CORS.

## Routes and evidence

- `/`, `/predict`: live 28-label GoEmotions reading, actual detections, ranked
  scores, full disclosure, truncation notice and cancellation guards.
- `/compare`: saved DAIR.AI example IDs; three historical models. Optional
  `?example=...` prefills an ID. Its sole contextual entry is “Compare historical
  benchmarks” beneath Analyze; the route also supports direct navigation.
- `/research`: an editorial paper grounded in completed P11 artifacts.
- `/research/experiments`: all twelve validation runs, mean/sample SD controls,
  per-run provenance, rare-label paired differences and a separate frozen test.
- `/errors`, `/metrics`: compatibility redirects to
  `/research/experiments#historical`, preserving historical metrics, errors and
  confusion pairs through the existing API.
- `/about`: project context and limitations.
- `/interpret`: designed historical-unavailable page; no GoEmotions attribution.

Research data is generated by `scripts/export-research.mjs` from the repository's
original reports, metrics and provenance. `research-sources.lock.json` pins their
SHA-256 hashes. The export contains no weights or individual held-out predictions.
Exact source copies are served under `/research/sources/` for working downloads.
The normal dev/build workflow generates these ignored outputs first, then the
build verifies all sources and generated bytes; it never silently repins.

```powershell
npm --prefix frontend run research:generate
npm --prefix frontend run research:check
```

The first command regenerates only from matching pinned sources; the second is
a read-only check of existing outputs. `--pin` is for
initial creation; `--add-sources` explicitly adds newly inspected sources while
still verifying every existing pin. Never edit P11 results to repair a mismatch.
The 38 pinned originals, including all twelve experiment provenance files, belong
in the source checkpoint. A clean checkout can build research without model weights
or dataset rows once that checkpoint is committed. Generated JSON/download copies
are ignored; `src/data/research.ts` remains source. The geometry reference used by
tests is `tests/fixtures/ribbon-geometry.json`, not an internal engineering report.

## Verification

```powershell
npm --prefix frontend run lint
npm --prefix frontend run build
npm --prefix frontend test
```

Tests require the main Vite service on port 5173, FastAPI on port 8000 and installed
Chrome. They start an isolated in-process QA Vite service on port 5174 with an
unreachable API origin on port 65530, then close it. Keep those QA ports free.
This tests real connection refusal without stopping the user's API.

Playwright covers live inference, request races, isolated malformed/edge-case
responses, all six primary routes at four widths in both stored themes, eight
live result layouts, navigation, the full-motion override and offline research. Axe scans
cover populated disclosures, research, explorer, comparison and navigation.
Fixtures live only in test code and never enter the production bundle. The full
suite needs the separately provisioned frozen model and historical API artifacts;
see the root README for local setup and backend validation-fixture limitations.

See [art direction](../docs/reading_studio_art_direction.md) and
[validation](../docs/reading_studio_validation.md) for exact executed results,
screenshots, source provenance, motion review and verification limits.
